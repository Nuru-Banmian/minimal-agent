# 领域文档

## 布局

采用单上下文布局：领域术语放在根目录 `CONTEXT.md`，架构决策记录放在 `docs/adr/`。

## 探索前阅读

探索代码库前，阅读 `CONTEXT.md` 和与当前工作相关的 ADR。

文件不存在时，直接继续，无需提示缺失或建议提前创建。由 `domain-modeling` 技能在领域术语或决策明确后按需创建。

## 术语与决策

输出中的领域概念使用 `CONTEXT.md` 定义的术语，避免使用词汇表明确排除的同义词。

所需术语尚未收录时，先判断是否引入了项目不使用的概念；确有缺口时，记录为后续领域建模事项。

建议与现有 ADR 冲突时，明确指出对应 ADR 和重新考虑该决策的理由。
